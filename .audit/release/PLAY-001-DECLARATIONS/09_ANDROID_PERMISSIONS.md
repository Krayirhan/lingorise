## Flag for the release

**`SYSTEM_ALERT_WINDOW`** is the one permission genuinely worth a Play Console declaration-review pass before submitting Content declarations — it requires an explicit justification field in Play Console, and this run could not find a first-party code path that uses it (already flagged, unresolved, in `SPRINT-002-PRODUCT-QUALITY-RUNTIME-POLISH`'s and `RELEASE-001-BASELINE`'s own residual-risk tracking as "confirm/justify `SYSTEM_ALERT_WINDOW` and merged plugin permissions during Play declaration review" — this run reconfirms that same finding still applies, not a new discovery). Recommend the owner trace which specific dependency contributes it (likely `expo-dev-client` or a related Expo tooling package pulled in only for development builds — if so, it may not even appear in a true release-profile build depending on how EAS's production build excludes dev-only modules; the AAB inspected here IS the actual production build, so its presence here is real and should be explained in the Play declaration, not assumed away).

No source change was made — flagging only, per the "no unnecessary permission removal without a genuine release blocker" instruction and the active source-lock.
